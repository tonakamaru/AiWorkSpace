# ChatGPT の会話に送信する

## PowerShell から Luna 固定で起動

```powershell
.\Send-ChatGPT.ps1 -To github -Message 'こんにちは'
```

送信先は `chatgpt-targets.json` で管理します。詳しくは [CLI-USAGE.md](CLI-USAGE.md)。Codex デスクトップを起動した状態で、同梱 MCP に接続して送ります。別の Luna CLI セッションからの実送信と返答を確認済みです。ブラウザは不要です。

送信前に会話履歴を `history/<threadId>.jsonl` へ保存し、送信後のターンと返答を追記します。標準出力は今回の完成済み返答本文のみ、進捗は標準エラーです。履歴は Git 管理対象外です。

## ブラウザ不要の直接送信版（別セッション向け）

`chatgpt-direct.js` を Codex の `functions.exec` で実行すると、会話IDを指定して送信・読み取りできます。対象会話をブラウザで開く必要はありません。初期設定は読み取りのみです。

詳しい使い方と別セッションへ貼り付ける依頼文は [CHATGPT-DIRECT-USAGE.md](CHATGPT-DIRECT-USAGE.md) にあります。Codex の会話操作ツールが使える環境が必要で、Node.js 単体では動きません。

## ブラウザ操作版

`chatgpt-send.js` は、Codex のブラウザ操作環境（`cua_repl` / `cua`）で使う JavaScript です。今回行った「開いている会話を選ぶ → 入力する → 送信する」を再利用できる形にしています。

## 使い方

1. Codex から操作できるブラウザで、送信先の ChatGPT の会話を開きます。
2. `chatgpt-send.js` の `TARGET_URL` をその会話の URL に、`MESSAGE` を送信したい文章に変更します。
3. Codex に「chatgpt-send.js を読み、ブラウザ操作環境で実行して、この内容を送信して」と依頼します。

ブラウザ操作環境を初めて使う場合、Codex は先に `await cua.getState();` だけを実行し、返された操作仕様を確認してからスクリプトを実行します。スクリプトの内容は `cua_repl` に渡して実行します。

これは Node.js やブラウザの開発者コンソールで単独実行するプログラムではありません。`cua` と `nodeRepl` は Codex のブラウザ操作環境から提供されます。

## 動作

- URL が完全一致する開いているタブだけに送信します。
- 対象が見つからない場合や複数ある場合は停止します。
- 入力途中の文章や生成中の回答がある場合は停止します。
- 送信の自動再試行はしません。
- 実行すると実際にメッセージを送信します。回答の取得・待機は含みません。

日本語版 ChatGPT の、この作業で確認した画面構造を使用しています。UI や表示言語が変わった場合は調整が必要です。

2026年9月19日、ユーザーの依頼でスクリプトの処理を `cua_repl` で実行し、実際の会話への送信に成功しました。入力欄が空になったことと、送信した文章が会話に表示されたことを確認済みです。送信先の ChatGPT からも「アクセスできました」と回答がありました。エラー時の分岐は実動作テストしていません。
